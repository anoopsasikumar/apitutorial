Chapter 1

The Problem

Why do apps need a special way to talk to each other?

A question you've probably never asked

When you check the weather on your phone, where does that number actually come from? Your phone doesn't have its own thermometer measuring the atmosphere. Somewhere, a government meteorological department has that data on a computer. Your weather app needs to ask that computer for it.

Same story everywhere: your UPI app asking a bank for your balance, a currency converter asking for today's exchange rate, or you wanting to pull GDP figures from the World Bank into your own R script. In every case, one program needs data or a service that lives on someone else's computer.

Why not just... look at their website?

You could open the World Bank's website, find the number, and type it into your spreadsheet by hand. That works once. It falls apart the moment you need:

✦ The same number for 190 countries, not one.
✦ Data that updates every day, not once.
✦ A program (not a human) to fetch it automatically.

Websites are built for humans to read with their eyes — headings, menus, images. They're not built for one computer program to politely ask another program for just one specific number. That requires a different kind of doorway.

Real-world analogy

A restaurant's dining room is designed for humans — menus, tables, ambience. But the kitchen also has a separate delivery entrance at the back, built specifically for suppliers dropping off exact orders: "20kg rice, 4pm, dock B." No decoration needed — just a precise, reliable way to hand over exactly what was asked for.

An API is that back entrance for computer programs.

This guide will explain, from scratch, how that back entrance works — no coding experience assumed.

✦ Quick check
Why can't a program just "read" a website the way a human does?
Programs are not allowed to open websites
Websites are designed for human eyes, not for programs requesting exact, structured data automatically
Websites don't contain any real data
Websites are built for visual browsing. Programs need a more precise, structured doorway to request and receive exact pieces of data — that's what an API provides.
Chapter 2

What is an API?

The waiter who carries your order to the kitchen and brings back your food.

The word itself

API stands for Application Programming Interface. That sounds abstract, so forget the acronym for a moment and focus on what it does: it's a defined, agreed-upon way for one piece of software to ask another for something, and get a reliable answer back.

Real-world analogy: the restaurant waiter

You (the app) don't walk into the kitchen (the server) and cook your own food. Instead:

1. You tell the waiter (the API) what you want, using the menu's language — "Table 4 would like one Chicken Biryani."
2. The waiter carries this precise request to the kitchen.
3. The kitchen prepares it and hands it back to the waiter.
4. The waiter delivers it to your table in a form you can use — on a plate, not as raw ingredients.

You never need to know how the kitchen is organised, what stove they used, or who chopped the onions. You just need to know the menu (what you're allowed to ask for) and trust the waiter to deliver it correctly.

In technical terms

An API is a set of rules published by whoever controls the data or service (the "kitchen"), describing exactly what you're allowed to ask for and what you'll get back. When you follow those rules, you don't need to know anything about their internal systems, database, or programming language.

An API you use every day without knowing it

When you check the weather on your phone, the weather app is not measuring the atmosphere itself. It sends a request to a meteorological service's API — something like "give me the current temperature for Thiruvananthapuram" — and receives back a precise, structured answer. The app then draws that nicely on your screen with a little sun or cloud icon.

Why researchers should care

Instead of manually visiting the World Bank's website, searching for "GDP of India," and copy-pasting a number into Excel — one at a time, for every country and every year — an API lets you write a script that asks for exactly the data you need and receives it directly, ready for analysis. What would take hours of clicking becomes a few lines of code, and it can be re-run every time the data updates.

✦ Quick check
In the restaurant analogy, what does the API represent?
The food itself
The kitchen
The waiter who carries requests and responses between you and the kitchen
The API is the messenger and rulebook — it defines how you ask for things and delivers the answer, without you needing to know how the kitchen (the underlying system) actually works.
Chapter 3

Anatomy of a Request

Most APIs you'll encounter are asked for things using ordinary web addresses.

The most common kind: web APIs

There are several types of APIs, but the overwhelming majority you'll meet as a researcher are web APIs — you ask for data using a URL (a web address), the same kind you type into a browser. The difference is that instead of getting back a pretty webpage, you get back raw, structured data.

Breaking down a URL request

Let's dissect a real example — asking a free weather service for the current temperature in Thiruvananthapuram:

https://api.open-meteo.com/v1/forecast?latitude=8.52&longitude=76.94¤t=temperature_2m
The base address (which service you're asking)
The endpoint (what kind of data — a "forecast")
Parameters (location — Thiruvananthapuram's coordinates)
More parameters (which specific value you want)

The four parts, explained

Base URL — Which service you're talking to. Every API publishes one, like a shop's street address.

Endpoint — Which specific "menu item" you want from that service. A weather API might have separate endpoints for /forecast, /historical, and /air-quality. Think of endpoints as different counters within the same shop.

Parameters — The details of your specific order, starting after a ?. Each one is written as name=value, joined by & symbols. This is exactly like filling in blanks on an order form: latitude, longitude, which measurement you want.

Method (not visible in the URL, but important) — Most simply "ask for" data using a method called GET. This is the same thing your browser does every time you visit any webpage — you're already using GET requests dozens of times a day without knowing it.

Real-world analogy

Filling in a library request slip: "Book title: ___, Author: ___, Section: ___." The parameters are the blanks you fill in. The endpoint is which request slip you picked up (fiction request vs. journal request). The base URL is simply which library you walked into.

Good news

You don't need to memorise this structure. You'll usually copy an example URL from an API's documentation page and just change the parameter values to what you need.

✦ Quick check
In a request URL, what do "parameters" specify?
Which company owns the API
The specific details of your request, like location or date
The programming language used to build the API
Parameters are the details you fill in — like coordinates for a weather request or a currency code for an exchange rate. They come after the ? in the URL.

Chapter 5

Anatomy of a Response

What comes back from an API, and how to read it.

JSON: the universal language of APIs

Almost every API you'll encounter replies using a format called JSON (JavaScript Object Notation — but don't worry about the name). It's just a simple, structured way of writing down labelled information, designed to be easy for both humans and computers to read.

A response, piece by piece

Here's what the weather demo above actually receives, simplified:

Response from the API (JSON)
{
  "latitude": 8.52,
  "longitude": 76.94,
  "current": {
    "temperature_2m": 29.4,
    "time": "2026-07-30T14:00"
  }
}

Reading this structure

✦ Everything sits inside curly braces { } — think of this as one "form" of information.
✦ Each line is a key (the label, in quotes, before the colon) and a value (the actual data, after the colon) — exactly like a labelled field: "temperature_2m": 29.4 means "the field called temperature_2m has the value 29.4."
✦ Values can nest inside other values — notice "current" contains its own mini-form with more keys inside it. This lets APIs organise complex, layered information (a forecast for many days, each with many hours, each with many measurements).
✦ Text values are wrapped in quotes ("2026-07-30T14:00"); numbers are not (29.4).

Real-world analogy

JSON is like a filled-in form with labelled boxes: Name: ___, Age: ___, Address: { Street: ___, City: ___ }. Anyone — human or computer — can look at the label and instantly know what the value next to it means, even without seeing the original blank form.

Why this format specifically?

Because every value has a clear label, a program can reliably pull out exactly the piece it needs — say, just the temperature — without a human needing to read and interpret sentences. This is precisely what makes automated, repeatable data collection possible.

✦ Quick check
In JSON, what is the purpose of the "key" in a key-value pair?
It labels what the value actually represents
It encrypts the data for security
It's just decoration and can be ignored
The key is the label — like "temperature_2m" — that tells you (and any program reading it) exactly what the adjacent value means.
Chapter 6

API Keys

Why some APIs ask you to identify yourself before letting you in.

Why the weather demo needed no key

The demo you tried in Chapter 4 worked instantly with no login. Some APIs are fully open like this — usually free services with generous usage limits, meant to be tried easily. But most APIs, especially ones tied to an account or with valuable data, require an API key before they'll respond.

What is an API key?

An API key is a long, unique string of letters and numbers — something like a1b2c3d4e5f6... — that identifies you (or your project) to the API provider. You include it with every request, and the server checks it before replying.

Real-world analogy

A library card. Anyone can walk into the public reading room (an open API), but to actually borrow books (access more data or a paid service), you need to show your card. The librarian checks your card, confirms you're a registered member, and only then hands over the book.

Why providers require keys

✦ Tracking usage — knowing who is making requests, and how many.
✦ Rate limiting — free accounts might get 1,000 requests/day; paid accounts get more (covered in the next chapter).
✦ Billing — some APIs charge per request; the key identifies which account to bill.
✦ Security — preventing anonymous, unlimited hammering of their servers.

How you'd typically get and use one

1
Sign up on the API provider's website (often free for basic access).
2
Find your key in your account dashboard, usually under something like "API Keys" or "Credentials."
3
Include it in your request — usually as another parameter in the URL, like &apikey=your_key_here, or sometimes in a separate part of the request called a "header."
Example — a request that needs a key
https://api.exchangerate.example.com/v1/latest?base=USD&symbols=INR&apikey=a1b2c3d4e5f6
Treat your key like a password

Never paste your API key into a public GitHub repository, a shared script, or a forum post. Anyone who has it can use your account's quota (or run up your bill, if it's a paid service). If you're teaching or sharing code, use a placeholder like YOUR_API_KEY_HERE and let each person add their own.

Chapter 7

Errors & Status Codes

What it means when an API says no — and how to read the message.

Status codes: a quick health report

Every single API response comes with a status code — a three-digit number that instantly tells you whether your request succeeded, and if not, roughly why. You've likely seen one already: the famous 404, which means "not found."

✅ 200 — OK▶

Everything worked. The data you asked for is in the response, exactly as expected. This is the code you want to see.

❌ 400 — Bad Request▶

Something about your request was malformed — a missing parameter, wrong format, or typo. This is usually a mistake in how you built the URL. Check the API's documentation for the exact spelling and required fields.

🔒 401 — Unauthorized▶

You didn't provide a valid API key, or forgot to include one. Go back and check Chapter 6 — make sure your key is correctly included in the request.

🔍 404 — Not Found▶

The endpoint or resource you asked for doesn't exist. Often a typo in the URL, or you're asking for a country code or date that isn't in the data.

⏳ 429 — Too Many Requests▶

You've hit a rate limit — the maximum number of requests allowed in a given time window (say, 60 requests per minute). Wait a bit before trying again, or check if you need a higher-tier plan.

💥 500 — Internal Server Error▶

Something broke on the API provider's end — not your fault. Try again later, or check the provider's status page if this persists.

What is a "rate limit," really?

Almost every API restricts how often you can ask it for things, to keep their servers running smoothly for everyone. A typical free plan might allow 60 requests per minute or 1,000 requests per day. If you're pulling data for, say, 190 countries in a loop, you may need to add small pauses between requests, or batch your requests according to the provider's guidance.

Real-world analogy

A library might say "you may borrow up to 5 books per visit." Ask for a 6th, and you'll be politely turned away — not because anything is broken, but because you've exceeded the agreed limit. Come back later (or become a premium member) for more.

✦ Quick check
You get a 401 status code. What's the most likely cause?
The server crashed
Your API key is missing or invalid
You asked for data that doesn't exist
401 means "Unauthorized" — the server couldn't verify who you are, almost always because of a missing or incorrect API key.
Chapter 8

The World Bank Data API

Putting it together with an API directly relevant to economic research.

The World Bank API

The World Bank publishes an open, keyless API covering thousands of development indicators — GDP, inflation, population, and more — for almost every country, going back decades. No sign-up required.

Example request — India's GDP
https://api.worldbank.org/v2/country/IND/indicator/NY.GDP.MKTP.CD?format=json

Reading this the way we learned in Chapter 3: the base URL is the World Bank's API address. The endpoint asks for country IND (India) and indicator NY.GDP.MKTP.CD (their code for GDP in current US dollars — every indicator has a unique code, listed in their documentation). The parameter format=json tells it to reply in JSON rather than another format.

Where to find indicator codes

The World Bank's data catalogue lists every indicator with its code — search for what you need (e.g., "inflation," "literacy rate") and copy its code into your request.

Why this matters for your workflow

Instead of manually downloading a spreadsheet each time you need updated figures, a script using this API can be re-run whenever you need fresh data — for a revised draft, a referee response, or an updated teaching example — without repeating manual downloads.

Tools worth knowing about

✦ Postman — A free application for building and testing API requests without writing any code, useful for exploring an API before scripting against it.
✦ Your web browser — For simple, keyless GET requests, you can literally paste the URL directly into your browser's address bar and see the JSON response.
✦ R's httr or httr2 package / Python's requests library — The standard tools for calling APIs from within an actual analysis script, once you're ready to move from browsing to automating.
